# H5支付功能优化工作说明

## 项目概述
本次工作主要针对Flutter Web应用中的H5支付功能进行了全面优化，解决了支付完成后用户被重定向到登录页面的问题，并提升了支付流程的用户体验。

## 主要问题
1. **支付后重定向问题**：用户完成微信H5支付后，应用重定向到登录页面而非预期的订单页面
2. **登录状态丢失**：支付过程中登录状态可能丢失，导致路由中间件拦截
3. **支付状态轮询问题**：轮询逻辑存在缺陷，可能导致状态更新不及时
4. **页面跳转方式**：支付页面跳转方式不当，可能影响用户体验

## 解决方案

### 1. 支付工具类优化 (`lib/utils/web_pay_util.dart`)

#### 1.1 轮询机制优化
- **轮询间隔调整**：从3秒调整为2秒，提升响应速度
- **最大轮询次数**：设置为150次（5分钟），确保足够的轮询时间
- **轮询逻辑优化**：先检查超时，再处理状态，避免逻辑错误

#### 1.2 页面可见性检测
- **新增功能**：添加页面可见性监听器，检测用户返回页面
- **立即检查**：用户返回页面时立即检查支付状态，无需等待轮询
- **监听器管理**：正确管理监听器的添加和移除，避免重复添加

#### 1.3 支付页面跳转优化
- **新窗口打开**：使用 `html.window.open(payUrl, '_blank')` 在新窗口打开支付页面
- **状态保持**：避免刷新当前页面，保持应用状态
- **用户体验**：用户可以在新窗口完成支付，原窗口保持状态

#### 1.4 支付状态查询优化
- **双重查询机制**：
  - 优先使用支付状态查询接口
  - 失败时回退到订单详情查询
- **状态映射**：正确映射微信支付状态到应用状态
- **错误处理**：完善的异常处理和日志记录

#### 1.5 资源管理优化
- **清理顺序**：先取消定时器和监听器，再清除回调函数
- **内存泄漏防护**：确保所有资源正确释放
- **重复调用防护**：防止重复添加监听器

### 2. 用户信息控制器优化 (`lib/services/user_info_ctl.dart`)

#### 2.1 登录状态检查方法
```dart
/// 检查并刷新登录状态
/// 用于支付完成后检查登录状态
Future<bool> checkAndRefreshLoginStatus() async {
  if (token.isEmpty) {
    LogUtils.d('Token为空，用户未登录');
    return false;
  }
  
  // 如果已经有用户信息且登录状态为true，直接返回
  if (_isLogin.value && _profile.value.id.isNotEmpty) {
    LogUtils.d('用户已登录，无需刷新');
    return true;
  }
  
  // 尝试重新获取用户信息
  LogUtils.d('尝试刷新用户登录状态');
  await getProfile();
  return _isLogin.value;
}
```

#### 2.2 用户信息获取优化
- **错误处理**：获取用户信息失败时正确设置登录状态为false
- **异常处理**：异常情况下清理用户数据
- **状态同步**：确保登录状态与用户数据一致

### 3. 路由中间件优化 (`lib/routes/route_middleware.dart`)

#### 3.1 中间件逻辑
```dart
/// 路由中间件
/// 处理路由拦截，权限验证等
class RouteMiddleware extends GetMiddleware {
  @override
  RouteSettings? redirect(String? route) {
    return UserInfoCtl.to.isLogin ? null : const RouteSettings(name: AppPages.login);
  }
}
```

- **简洁高效**：简化中间件逻辑，直接检查登录状态
- **性能优化**：避免不必要的异步操作
- **可靠性**：确保登录状态检查的准确性

## 技术细节

### 1. 支付状态轮询流程
1. 发起支付时开始轮询
2. 每2秒查询一次支付状态
3. 用户返回页面时立即检查
4. 支付完成或超时时停止轮询
5. 调用相应的回调函数

### 2. 页面可见性检测
```dart
_visibilityListener = (event) {

    LogUtils.d('页面重新可见，立即检查支付状态');
    _checkPaymentStatusOnPageVisible();

```

### 3. 支付状态映射
- `SUCCESS` → `PAY_STATUS_SUCCESS`
- `USERPAYING` → `PAY_STATUS_PENDING`
- `NOTPAY` → `PAY_STATUS_PENDING`
- `PAYERROR` → `PAY_STATUS_FAILED`
- `REVOKED` → `PAY_STATUS_CANCELLED`
- `CLOSED` → `PAY_STATUS_CANCELLED`
